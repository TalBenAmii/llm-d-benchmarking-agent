Features

  • Core flow: interview → plan → deploy → run → explain
  • UI: approval cards, run stepper, result charts, wizard, share
  • Runs: the real llmdbenchmark CLI in-pod (optional K8s Job mode); sweeps, retry, resume, fault classify
  • Analysis: SLO verdicts, goodput, Pareto frontier, A/B, trends
  • Execution: policy for dedicated commands; shell classifier; approval by default; backend credentials
  • Deploy: one-command kind install, Helm + RBAC, simulate mode, sibling MCP server
Deployment view and scope. This diagram covers the browser and MCP interfaces, shared tools, upstream repositories, and benchmark environment. The assistant backend runs locally or as an in-cluster service. Claude and Codex engines share the tool registry; Codex subscription setup is documented for the local path. The standalone llm-d-bench-mcp/ adapter exposes the same tools to an external MCP client.

Auto-approve can waive command cards. run_shell uses a heuristic classifier, not the dedicated-command allowlist. MCP execution relies on the client’s tool permissions. The four validation gates cover arguments, SessionPlan/catalog consistency, generated config structure and report structure. Plan approval is not a universal execution prerequisite.

SIMULATE=1 executes read-only probes and returns synthetic results for approved mutations. A real model/GPU deployment is distinct from both simulation and CPU-kind testing.
